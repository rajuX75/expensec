## 2026-08-22 - Avoid Instantiating Calendar Objects in Reactive Flows Loops
**Learning:** In Jetpack Compose / StateFlow architecture, calling `Calendar.getInstance()` inside loops over transactions (e.g., `transactions.forEach { tx -> ... }`) within `combine`/`map` flows causes high garbage collection thrashing and CPU overhead (e.g. up to `6 * N` or `B * N` heavy object allocations per emission). Pre-computing month boundary timestamps `[startMs, endMs)` once per emission allows checking `tx.date >= startMs && tx.date < endMs` using primitive comparisons with 0 allocations.
**Action:** When performing period or date-range filtering over list items in Kotlin StateFlows, pre-calculate target timestamp bounds once outside the loop instead of creating `Calendar` instances per item.
